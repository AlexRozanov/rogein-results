# Формат данных SFR-чипа

Чип SFR — это ISO 15693 (NFC-V). Память нарезана на **блоки по 4 байта**. Логика «номер участника + отметки КП» лежит поверх этой памяти: полевые станции и телефон пишут одни и те же блоки.

Источники в репозитории:

- чтение/запись по NFC: `android/chip-parse` (`SfrChipParser`, `SfrChipMemory`) и `android/app/.../Iso15693MemoryReader.kt`
- USB-станция: `programs/basic` (`STFform.cpp`, `STFform.h`)

---

## 1. Железо

| | |
|---|---|
| Радио | ISO 15693 / NFC-V, 13.56 МГц |
| UID | 8 байт, обычно `E0:…` |
| Размер блока | 4 байта |
| Число блоков | 64 или 128 (телефон спрашивает Get System Information) |
| Ёмкость отметок | блоки 5…N−1 → **59** (чип на 64 блока) или **123** (на 128) |

Телефон читает только NFC-V (`NfcAdapter.FLAG_READER_NFC_V`).

Станция по USB — HID **VID `0x2047`, PID `0x0301`**, отчёт 64 байта.

---

## 2. Карта памяти чипа участника

Порядок байт **логический (HID / SFR basic)**: `[0] [1] [2] [3]`.

Некоторые приложения (NFC Tools) показывают каждый блок **задом наперёд**. Телефон пробует оба порядка и выбирает более правдоподобный дамп.

| Блок | Назначение | Формат (HID) |
|------|------------|----------------|
| 0 | не используется | `00 00 00 00` |
| 1 | время очистки | `00 HH MM SS` (время в BCD) |
| 2 | не используется | `00 00 00 00` |
| 3 | логический номер | `lo hi 00 00` |
| 4 | указатель | `end 00 00 00` |
| 5 … `end` | отметки | `КП HH MM SS` |
| `end+1` … последний | старый мусор или нули | не читать |

**Указатель `end`** — номер **последнего занятого** блока отметок (не «следующий свободный»).

- Чип только что выдан: `end = 5`, блок 5 пустой → отметок нет.
- Одна отметка в блоке 5 → `end = 5`.
- Старт + КП + финиш в блоках 5, 6, 7 → `end = 7`.

Читать отметки: блоки `5 … end` включительно, пропуская `КП = 0`.

## 3. Кодирование полей

### Логический номер (блок 3)

```
id    = byte0 + byte1 * 200
byte0 = id % 200
byte1 = id / 200
```

Диапазон в Rogein: **1…39999** (станция при записи берёт `id % 40000`).

Пример: номер **606** → `06 03 00 00`  
`6 + 3×200 = 606`.

Станция при чтении считает то же через полубайты:

```
hi(byte1)×3200 + lo(byte1)×200 + byte0
```

Это тот же `byte0 + byte1×200`.

### Время — BCD, не двоичное

Байт `0x45` значит **45**, не 69.

```
bcd(n) = ((n / 10) << 4) | (n % 10)
```

Часы 0–23, минуты и секунды 0–59. Невалидный BCD (полубайт > 9) — блок игнорируется.

### Отметка (блоки ≥ 5)

```
[ КП: 1 байт ] [ час BCD ] [ мин BCD ] [ сек BCD ]
```

КП — обычное число 1…255, **не BCD**.

Зарезервированные номера:

| КП | Смысл |
|----|--------|
| **240** | финиш |
| **241** | старт |
| **243** | станция очистки (на чипе участника обычно не лежит как отметка) |

Пример: КП 31 в 10:15:45 → `1F 10 15 45`.

### Время очистки (блок 1)

`00 HH MM SS` — тот же BCD. Ставится при выдаче и очистке.

---

## 4. Порядок байт: HID и NFC Tools

| Режим | Как лежат 4 байта блока |
|--------|-------------------------|
| `Hid` | как в SFR basic и USB-станции: `[КП][ЧЧ][ММ][СС]` |
| `NfcTools` | те же 4 байта наоборот: `[СС][ММ][ЧЧ][КП]` |

Телефон читает сырые блоки, строит обе интерпретации и выбирает лучшую по эвристике: валидный `end`, число отметок, наличие номера, время очистки, последняя отметка = финиш, времена не убывают.

При записи телефон кладёт на чип байты в том порядке, в котором этот экземпляр чипа уже читался (`SfrChipMemory.toWire`).

---

## 5. Пример с реального чипа

Экспорт NFC Tools (байты уже перевёрнуты):

```
Сектор 01: 41 42 11 00   → HID 00 11 42 41  → очистка 11:42:41
Сектор 03: 00 00 03 06   → HID 06 03 00 00  → номер 606
Сектор 04: 00 F0 00 1B   → HID 1B 00 F0 00  → end = 0x1B = 27
Сектор 06: 50 45 11 2D   → HID 2D 11 45 50  → КП 45 в 11:45:50
Сектор 1B: 00 39 12 F0   → HID F0 12 39 00  → финиш 12:39:00
```

Отметки в блоках 5…27; пустой блок 5 пропускается (`КП = 0`).

## 6. USB-протокол станции (`programs/basic`)

Кадр к станции:

```
HID 64 байта:
  [0] = 0x3F
  [1] = длина внутреннего пакета
  [2…] = пакет

Пакет:
  FD | данные | checksum | FE | 00
```

**Checksum** — сумма байт `данные` с переносом:

```
s = s + b
s = (s & 0xFF) + (s >> 8)
```

Реализация: `TSFRst::CheckSum` и кадр `TUniCommand` в `STFform.h`.

### Команды (поле `данные`)

**Чтение блока** (код `01`):

```
01  <номер_блока>
```

Ответ: эхо команды, затем 4 байта блока. Станция склеивает их в 8 hex-цифр, например `1F101545`.

**Запись блока** (код `02`):

```
02  <номер_блока>  b0 b1 b2 b3
```

**Сигнал / писк** (код `03`):

```
FD 03 01 <cs> FE
```

В HID это выглядит так: `3F 05 FD 03 01 04 FE …`

Вызывается после успешной выдачи, финиша и настройки станции (`SendSignalCommand`).

### Выдача чипа на станции (`FormatCard`)

Пишет все 128 блоков:

- все → `00000000`
- блок 1 → `00` + текущее время как BCD (`00HHMMSS`)
- блок 3 → номер `%200` / `/200`
- блок 4 → `05000000` (указатель = 5)

После полного круга — писк, опционально номер++.

### Чтение финиша на станции (`PermReader`)

1. Блок 4 → `end`
2. Блок 3 → номер
3. Блоки 5…`end` → отметки, время из hex как `HH:MM:SS`
4. КП 241 → `S`, 240 → `F`
5. Писк, строка в файл

Формат SFR:

```
SFR;<дата>;<время_станции>;<номер>;<КП или S/F>;<HH:MM:SS>;...
```

Альтернативный вывод — построчно в стиле SportIdent (`SIreaderFormat`).

## 7. NFC на телефоне

ISO 15693:

| Команда | Код |
|---------|-----|
| Read Single Block | `0x20` |
| Write Single Block | `0x21` |
| Get System Information | `0x2B` |

Флаги перебираются, пока чип не ответит: addressed `0x20` / `0x22` / `0x60` / `0x62`, unaddressed `0x00` / `0x02` / `0x40` / `0x42`. После записи блок читается и сравнивается.

Кадр чтения с UID:

```
[flags] 20 [UID 8 байт] [block]
```

Запись:

```
[flags] 21 [UID 8 байт] [block] [4 байта]
```

Ответ: первый байт, бит 0 = ошибка. Данные блока — следующие 4 байта.

Get System Information: после flags в ответе UID (8 байт), затем опционально DSFID / AFI / размер памяти. Число блоков = `blocksMinus1 + 1`, размер блока должен быть 4.

### Выдача (номер + очистка отметок)

Порядок важен: сначала прячут старые отметки, потом затирают. **Блок 3 при очистке не трогают**, номер пишется в конце.

1. блок 4 ← `05 00 00 00` (указатель на пустое)
2. блоки 5…старый `end` ← нули
3. блок 1 ← время очистки
4. блоки 0 и 2 ← нули
5. блок 3 ← логический номер

После выдачи указатель = 5, отметок нет.

Станция при `FormatCard` затирает все 128 блоков и тоже ставит указатель 5; телефон затирает только занятый диапазон и не трогает номер, пока не запишет новый.

### Тестовая запись прохождения

Очистка как выше, затем отметки в 5, 6, … и указатель `end = 4 + N`.

## 8. Как телефон читает

**Выдача и тесты** — полный дамп 0…N−1, затем обе интерпретации порядка байт.

**Финиш** — как станция, без хвоста памяти:

1. Get System Information → размер чипа (64 или 128). Этот размер запоминается отдельно, не как число прочитанных блоков.
2. Read блоки **3** и **4**.
3. Кандидаты указателя: байт 0 (HID) и байт 3 (NFC Tools). Читать `5…max(валидные end, 6)` — минимум до блока 6, чтобы отличить программатор станции.
4. Интерпретация `Hid` и `NfcTools` по уже прочитанным блокам, берётся лучший дамп.
5. Если логического номера нет — чип **не** ставится в очередь. Сообщение: роль программатора (старт / финиш / очистка / активный / пассивный / батарея) или «нет номера, выдайте на вкладке Выдача».

Блоки 0–2 на финише не читаются. Если очередной блок не ответил, берётся то, что успели прочитать.

Указатель может указывать дальше, чем удалось прочитать: тогда отметки из `5 … min(end, lastIndex)`.

## 9. Память станции КП (не чип участника)

Через те же USB read/write блоков программа настраивает **саму станцию**:

| Запись | Смысл |
|--------|--------|
| блок 4 = `00010000`, блок 5 = `КП + время`, блок 6 = `00250000` | роль станции; время в блоке 5 — часы станции |
| блок 5, КП = 1…255, кроме 240/241/243 | обычный пункт (кнопка Control в SFR basic) |
| блок 5, КП = 243 | станция очистки |
| блок 5, КП = 241 | старт |
| блок 5, КП = 240 | финиш |
| блок 4 = `02020000` | активный режим (Active On) |
| блок 4 = `03030303` | пассивный режим (Active Off) |
| блок 4 = `05050505` | сброс / проверка батареи |

Это конфиг станции по USB. С телефона тот же шаблон пишется **на чип** (вкладка «Станция»): номер и старые отметки обнуляются (иначе финиш увидит прежнего участника). Затем этот чип прикладывают к полевой станции. Запись только из этого раздела и только после подтверждения.

На вкладке «Финиш» такой чип не принимается: нет логического номера, в ошибке указано, что делает карта.

**Активный режим** — станция постоянно ищет чип, кнопку нажимать не нужно. Нужен на соревнованиях и при температуре ≤ +5 °C. Сильно расходует батарею: если станцию оставить в этом режиме, батарея сядет меньше чем за месяц. Карта многоразовая.

**Пассивный режим** — возврат к обычному «нажать кнопку». Экономный, для тренировок при температуре выше +5 °C. Карта многоразовая, удобно выдать на снятие дистанции.

**Проверка батареи** (`Reset/Battery check`) — одноразовая карта. После отметки станция ~30 с проводит самодиагностику (светодиод горит постоянно), затем моргает **1–15 раз**. Меньше 7 миганий — батарею лучше заменить (на лето допускают меньше, на зиму — не ниже 7). Операция **сбрасывает часы станции** (инструкция SFR U5 manager, раздел «Дополнительные функции»; то же в [SFR instruction for organizers](http://www.sfr-system.com/instructions/SFR_instruction_for_organizers.pdf): *Battery check procedure cleared the real time clock*). Напряжение на чип не пишется: результат только миганиями на станции.

Часы станции выставляются не отдельной командой, а при записи роли: в блок 5 пишется текущее время (в SFR basic — часы ПК плюс 4 секунды и обратный отсчёт). После проверки батареи роль (КП / старт / финиш / очистка) нужно записать снова.

## 10. Сводка потока

```
станция КП в поле          чип                  телефон / финишная станция
     |                      |                           |
     |  Write Block 5+N     |                           |
     |  КП + BCD-время      |                           |
     |  end++               |                           |
     |--------------------->|                           |
                            |  Read blocks 0..N         |
                            |-------------------------->|
                            |  номер из блока 3         |
                            |  отметки 5..end           |
```

Логический слой один: **4 байта на слот, BCD-время, номер как `lo + hi×200`, указатель в блоке 4**. Меняется только транспорт: ISO 15693 с телефона или HID-кадр `FD … FE` через станцию.
