# Формат данных Sportiduino (NTAG / CTS)

Sportiduino — открытая система электронной отметки на NTAG213/215/216 (ISO 14443A Type 2). Clever Timing System (CTS, «Clevear») пишет на чип **тот же** формат: страницы по 4 байта, Unix-время, спецномера станций 240/245/248/249.

Это не SFR. Другое радио, другая карта памяти, другое время. Общее с SFR — только идея «слот = КП + время».

Рядом: [sfr-chip.md](sfr-chip.md).

Источники формата:

- [sportiduino/docs/ru/Cards.md](https://github.com/sportiduino/sportiduino/blob/master/docs/ru/Cards.md)
- прошивка: `CARD_PAGE_INIT = 4`, `CARD_PAGE_INIT_TIME = 5`, `CARD_PAGE_START = 8`
- разобранный дамп CTS: `export.hex` (NTAG216, 17 отметок, финиш 245)

Как и в описании SFR, здесь нет markdown-таблиц.

---

## 1. Железо

```
радио          ISO 14443A Type 2, 13.56 МГц  (не NFC-V)
чип            NXP NTAG213 / 215 / 216  (ещё умеет Mifare Classic, реже)
UID            7 байт, обычно 04:…
страница       4 байта  (как «блок» SFR, но нумерация с 0 как у NTAG)
ёмкость        NTAG213 → 32 отметки   (пользовательские стр. 4…39)
               NTAG215 → 120 отметок  (стр. 4…129)
               NTAG216 → 216 отметок  (стр. 4…225)
```

Телефон видит такой чип как **NfcA / Mifare Ultralight**, не как NfcV. Кадры SFR (`0x20` Read Single Block) до него не доходят.

Тип NTAG читается из Capability Container, страница 3, байт 2:

```
стр. 3    E1  10  <size>  00

size  0x12  NTAG213
      0x3E  NTAG215
      0x6D  NTAG216
```

Команды Type 2:

```
0x30  READ   — 4 страницы подряд (16 байт)
0xA2  WRITE  — одна страница (4 байта)
```

## 2. Карта памяти чипа участника

Страницы 0–3 и хвост — железо NTAG. Страницы 4–7 — заголовок Sportiduino. С 8-й — отметки. Указателя «последний занятый» нет: станция ищет свободную страницу с конца.

```
стр.   байты                         смысл
────   ───────────────────────────   ──────────────────────────────────────
  0    UID0 UID1 UID2 BCC0           UID, часть 1
  1    UID3 UID4 UID5 UID6           UID, часть 2
  2    BCC1 INT  lock lock           служебное NTAG
  3    E1   10   size 00             Capability Container
  4    n0   n1   00   ver            номер чипа + версия прошивки
  5    t3   t2   t1   t0             Unix-время очистки, big-endian
  6    ??   ??   ??   ??             резерв (info / last-record)
  7    ??   ??   ??   ??             резерв
  8    КП   t2   t1   t0             первая отметка
  …    КП   t2   t1   t0             следующие
  k    00   00   00   00             первая свободная — дальше не читать
225    (NTAG216, последняя user)     не заходить в конфиг 226…
226+   CFG / PWD / PACK              не трогать
```

Мастер-чип программатора станции — другой формат: в **третьем** байте страницы 4 лежит `FF`. Обычный чип участника там `00`.

## 3. Кодирование полей

### Номер чипа (страница 4)

```
стр. 4    [ n0 ] [ n1 ] [ 00 ] [ ver ]
            └──────┘      │      └── младшая версия прошивки станции
            номер         └── 00 = участник,  FF = мастер-чип
```

Первые два байта — программируемый номер. В серийном протоколе Sportiduino номер часто little-endian (`n0 + n1×256`). Unix-время на той же карте — big-endian; без второго дампа с известным номером endian номера лучше не фиксировать жёстко, а принимать оба, если один даёт правдоподобное 1…9999.

`ver = 8` — прошивка v3.8.x, `9` — v3.9.x.

### Время очистки (страница 5)

Четыре байта Unix **big-endian**. Это полная дата и время, не BCD суток.

```
стр. 5    6A CA 49 21     = 0x6ACA4921
                          = 2026-10-10 14:18:09 UTC
                          = 2026-10-10 17:18:09 MSK
```

Старший байт (`0x6A` в примере) подставляется к каждой отметке.

### Отметка (страницы ≥ 8)

В страницу не влезает КП + 4 байта Unix, поэтому на чип пишут только младшие 24 бита времени. Полный Unix восстанавливается из страницы 5:

```
[ КП: 1 байт ] [ unix bits 23…16 ] [ 15…8 ] [ 7…0 ]

unix_punch = (init_unix & 0xFF000000) | time24
```

Если `time24` меньше младших 24 бит очистки (переполнение 24-битного счётчика ≈ 194 дня), старший байт увеличивают на 1. На обычном старте это не встречается.

КП — обычное число 1…255, не BCD.

### Спецстанции

```
240    старт          (у SFR это финиш)
245    финиш          (у SFR финиш — 240)
248    проверка
249    очистка        (на чипе участника обычно не как отметка:
                       очистка = перезапись стр. 5 и затирание 8+)
```

Старт 240 на чипе может отсутствовать: массовый старт, время берётся из протокола.

## 4. Пример с реального чипа CTS

Файл `export.hex` (Intel HEX), NTAG216, 924 байта (`0x0000…0x039B`).

```
UID              04:89:41:E2:EA:14:90
CC               E1 10 6D 00                 → NTAG216
стр. 4           47 FC 00 08                 номер 47 FC, не мастер, ver 8
стр. 5           6A CA 49 21                 очистка 2026-10-10 17:18:09 MSK
стр. 6–7         00 00 00 00
AUTH0            0xBD                        пароль выключен
```

Отметки со страницы 8. Старший байт Unix везде `0x6A` из страницы 5. Времена — MSK (UTC+3). Старта 240 нет.

```

  9    22 CA 59 79    34    2026-10-10 18:27:53    2:01
 10    59 CA 59 96    89    2026-10-10 18:28:22    0:29
 11    70 CA 59 CD   112    2026-10-10 18:29:17    0:55
 12    7C CA 59 EC   124    2026-10-10 18:29:48    0:31
 13    6E CA 5A 44   110    2026-10-10 18:31:16    1:28
 14    35 CA 5A 95    53    2026-10-10 18:32:37    1:21
 15    6F CA 5B 08   111    2026-10-10 18:34:32    1:55
 16    57 CA 5B 6F    87    2026-10-10 18:36:15    1:43
 17    6D CA 5B C2   109    2026-10-10 18:37:38    1:23
 18    7B CA 5C 2F   123    2026-10-10 18:39:27    1:49
 19    39 CA 5C 64    57    2026-10-10 18:40:20    0:53
 20    56 CA 5C AE    86    2026-10-10 18:41:34    1:14
```

## 5. Мастер-чипы (кратко)

Станция Sportiduino программируется не «магией в блоке 4 участника», как SFR, а отдельными мастер-чипами. Признак: страница 4, байт 2 = `FF`. Дальше тип задаёт первый байт (`248`…`255`: пароль, состояние, время, номер, сон, лог, настройки).

Для мобильного финиша мастер-чипы не нужны. Их достаточно отличать и не класть в очередь участников.

## 6. Чем это не SFR

```
                 SFR                         Sportiduino / CTS
радио            ISO 15693 NFC-V             ISO 14443A Type 2 (NTAG)
слот             блок                        страница (тоже 4 байта)
номер            lo + hi×200, 1…39999        uint16 на стр. 4
время            BCD HH:MM:SS, без даты      Unix, дата полная
указатель        блок 4 = last used          нет, ищут нули с конца
старт / финиш    241 / 240                   240 / 245
очистка          КП 243 + блок 1             стр. 5 = Unix, КП 249
порядок байт     HID vs NFC Tools            на NTAG обычно как записали
станция          magics на чипе участника    отдельные мастер-чипы
```

Телефон, который слушает только NFC-V, этот чип не увидит.

## 7. Мобильное приложение под оба формата

Слой «протокол / очередь / live» у систем почти общий: номер, список (КП, время), старт/финиш. Расходится транспорт NFC и парсер. Ниже три рабочих варианта и рекомендация.

### Вариант A — одно приложение, автоопределение радио (рекомендуется)

На поднесённом теге смотрят технологию, дальше вызывают свой ридер и парсер. UI финиша один.

```
Tag
 ├─ NfcV / ISO 15693     → SfrReader    → SfrChipParser
 └─ NfcA / Type 2        → NtagReader   → SportiduinoParser
                              ↓
                     ChipDump (общий)
                     system = sfr | sportiduino
                     id, punches[(cp, instant)], uid
                              ↓
                     очередь → протокол → live PUT
```

Android: в `enableReaderMode` добавить `FLAG_READER_NFC_A` к уже существующему `FLAG_READER_NFC_V` (и по-прежнему `SKIP_NDEF_CHECK`). Сначала `NfcV.get(tag)`, если null — `MifareUltralight.get(tag)` / `NfcA`.

iOS: `NFCTagReaderSession(pollingOption: [.iso15693, .iso14443])`. В `didDetect` ветка `.iso15693` как сейчас, ветка `.miFare` — `NFCMiFareTag` команды `0x30` / `0xA2`. Entitlement тот же (платная Apple Developer Program).

Общая модель дампа:

```
ChipDump
  system:       sfr | sportiduino
  uid:          String
  logicalId:    Int?
  clearedAt:    Instant?          // SFR: время суток без даты
  punches:      [(cp, Instant)]
  raw:          пакет для отладки (блоки или страницы)

спец-КП зависят от system:
  SFR            старт 241, финиш 240
  Sportiduino    старт 240, финиш 245
```

Для SFR `Instant` собирают из даты события (или «сегодня») + BCD-часов. Для Sportiduino берут Unix как есть — полуночные гонки не ломаются.

Выдача:

```
SFR            блок 3 = номер, блок 4 = end 5, блок 1 = BCD, затирание 5…end
Sportiduino    стр. 4 = номер+ver, стр. 5 = Unix сейчас, нули с 8-й
```

Вкладка «Станция» пока остаётся SFR-only: мастер-чипы Sportiduino — отдельный формат и отдельный риск затереть участника. На финише мастер-чип (`стр.4[2] == 0xFF` или SFR без номера) — ошибка с ролью, в очередь не класть.

Плюсы: один APK, судья не выбирает систему, live один.  
Минусы: два NFC-стека, на части телефонов двойной poll чуть медленнее; тесты нужны на обоих чипах.

### Вариант B — переключатель «SFR / Sportiduino» в настройках

Пользователь заранее указывает систему. Reader mode включает только одно радио.

Плюсы: проще отлаживать, меньше сюрпризов на слабых NFC.  
Минусы: забытый переключатель = «чип не читается»; два пути в UI. Имеет смысл как скрытая отладка поверх варианта A, не как основной UX.

### Вариант C — два приложения / два flavor

Общий модуль протокола и live, разные `app-sfr` и `app-cts`.

Плюсы: нулевой риск спутать радио.  
Минусы: две установки, два обновления, двойной Review в App Store. Для текущего размера проекта избыточно.

### Что не стоит делать

Не пытаться «угадать формат» по содержимому одного и того же радио: чипы на разных антеннах. Сначала tech, потом парсер.

Не читать NTAG командами ISO 15693 и наоборот.

Не класть сырые SFR-блоки в Sportiduino-парсер: спец-КП зеркальные (240 — финиш у SFR и старт у Sportiduino), время разное. Нормализация — только после парсера, в `ChipDump`.

### Минимальный порядок работ, если делать A

```
1. Общий ChipDump с Instant и system (Android chip-parse + iOS SfrKit).
2. SportiduinoParser + фикстура export.hex (как тесты SFR).
3. NtagReader: READ 0x30 страницами, стоп на нулях после стр. 8.
4. Reader mode / polling на оба радио, развилка по tech.
5. Выдача Sportiduino (номер + Unix + wipe).
6. UI: бейдж системы на карточке финиша; станция — только SFR.
7. Live JSON: поле system, чтобы сайт не путал 240.
```

Шаги 1–4 уже дают читать оба чипа на финише. Станции Sportiduino и пароль NTAG можно не трогать, пока не появятся мастер-дампы и политика записи.
